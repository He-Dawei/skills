# me-guard — 删除 / 调试 / 外部操作安全闸门

命中下面任一关键词，**先停一秒过三问，再动手**：
删除、清空、覆盖、发布、上传、对外发送、付款、下单、订阅、账号、登录、授权、密钥、token、密码、cookie、安装依赖、改客户端配置。

## 三问（动手前必须能回答）

| 问 | 要回答什么 |
|---|---|
| **范围** | 影响哪些文件/目录/系统/人？数量级？（`ls` 数一下，别猜） |
| **风险** | 最坏结果是什么？会不会外泄数据、花钱、发出去不可撤回、动到别人的东西？ |
| **可逆** | 能不能撤销？有没有备份/回收站/git？撤销步骤是什么？ |

三问都答得上来 → 按下面的分级动手。答不上来 → **先查清，再动手**。

## 分级

| 级别 | 例子 | 做法 |
|---|---|---|
| **L0 只读** | 读文件、搜索、截图、查页面 | 直接做 |
| **L1 可逆本地写** | 新建文件、改自己的草稿、装到项目内 | 做，一句话说明 |
| **L2 不可逆本地** | 删除、覆盖、批量重命名、清缓存 | **先看目标**（`ls`/`cat` 确认就是这个），再删；范围大时先说清影响再执行 |
| **L3 对外 / 账号 / 资金 / 发布** | 发帖、发邮件、回复买家、提交表单、付款、下单、登录授权、改账号设置、push 到公共仓库 | **一律由用户本人手动执行。agent 只产出文档/草稿。** |

**审批闸门**：不装、不登录、不发布、不删除、不改客户端配置 —— 除非用户明确批准。涵盖 npm/pip 安装、git push、settings 修改、MCP 注册。

## 删除/覆盖前的最小动作

1. `ls` 或 `cat` **看清目标**是不是你以为的那个。
2. 确认不在关键路径上（不删源目录、不删 junction 指向的目录、不删 `.git`）。
3. 优先移到回收站/临时目录而不是硬删。
4. **警惕 `os.walk` 跟随 junction/软链接** —— 会删到源目录上（已有教训，见记忆 `codex-skills-sync.md`）。

## 密钥卫生

- **不把密码、Token、Cookie、API Key、验证码、私钥写进任何 Skill、记忆文件、脚本、日志、提交信息或回复正文。** 需要引用时写 `<REDACTED>` 或占位符。
- 写配置示例用 `YOUR_TOKEN_HERE` 这类占位符，绝不用真值。
- 发现凭证出现在不该出现的地方（被打印、被写进文件、被提交）→ **报告 + 建议轮换**，不要把它复制到别处、不要贴进对话。
- 不在对话里回显密钥全文；用户粘贴了 → 提醒一下并避免复述。

## 调试类任务走这里

不要自己发明调试流程。按情况读这几个已有 skill：

- 初次遇到 bug / 报错 / 测试失败 → `debugging-methodology`（5 步：复述错误、圈定影响、枚举原因、最小修复、定义验证）
- 长期跟的复杂 bug / 性能回归 → `diagnosing-bugs`
- 修过一次没好、或同一 bug 复发 → `diagnose-minimal-fix`
- 直觉判断优先于流程时的兜底 → `systematic-debugging`

调试时的安全约束：**不要在真实数据上试破坏性命令**；先备份或复制一份到临时目录；一次只改一处以便归因。

## 红线（长期有效，来自跨境项目与全局规则）

- 账号、资金、发布、回复买家：**用户本人手动执行**，agent 只产出文档。
- 不虚构：客户、评价、收益、从业年限、平台政策。
- 不承诺收款结果；不提供法律 / 财税 / 催收建议。
- 素材、字体、图片必须有使用权；sample 必须标 sample。
- **不点击任何人发来的站外链接。**
- 不臆造个人信息；不确定就去读 memory 或问用户。
