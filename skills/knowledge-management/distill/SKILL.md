# 蒸馏（distill）

把原材料压成**可复用的协议**，而不是读书笔记。

## 先把话说白

**蒸馏的目的：让 AI 真正把这本书读进去。**

人读书多了才有见识。AI 一样 —— **库里有过什么书，它回答相关问题时就有那套判断可用**，
不必每次联网现找、现拼。以前的人没有网络也能学富五车，靠的就是读书。

所以：**书是喂给 AI 的，不是只喂给人的。人看不看是人的选择。**

**蒸馏本质是结构化提示工程。** 它做的是：把散落在 300 页里的判断依据压成 1 页可执行的规则；
把「作者怎么想」从行文里反推出来，写成决策协议。

关于「得到的是**作者的思考协议**，不是他的直觉」——**这不是缺陷，这恰恰是它可用的原因**：
直觉不可传授也不可调用，**协议可以**。交付协议就是交付了能用的东西。

**两条必须守住的边界（防做假，不是限制目标）：**

- 不产生原材料里没有的知识 —— 编造即失效
- 原材料信息密度低（注水书、空话纪要），蒸出来必然是空话 —— 这种情况应当早退，不要硬蒸

> ⚠️ 本文件曾写「你没认真读过的书，蒸出来的东西你也不会用」——**该条已删除**（2026-09-27）。
> 它把蒸馏当成替人省事的摘要工具，方向与目的相反。

把「目的是让 AI 读过」这句原样告诉用户一次。

## ⚠️ 落库是必做步，不是可选项

**只出 skill 不落 LLM-Wiki = AI 没读过。** 下次问相关问题时它仍然一无所知。

所以蒸完必须落库（见文末「双产物」节）：

- **`sources/`** —— 原材料本身按分节落成来源笔记（原文进库，AI 的「读过」建立在原文可回溯之上）
- **`collections/`** —— 主题合集，双链指向来源
- **`concepts/`** —— **仅当该概念另有 ≥2 个独立来源支持时才建**。单本书 = 孤证，不建页

收尾前核对这三步是否真落地了。2026-09-27 实发过一次漏项（《富爸爸穷爸爸》只出了 skill，
vault 内搜「清崎／富爸爸」零命中），用户是靠自己发现的 —— 不要再让它发生。

## 五类原材料 → 五种蒸法

| 类型 | 蒸什么 | 产物怎么用 | 判定特征 |
|---|---|---|---|
| **工具书** | 方法论 | 遇到问题 → 直接套步骤 | 有操作步骤、清单、「第一步第二步」 |
| **非工具书** | 作者的思维框架 | 遇到问题 → 借他的角度想 | 有反复出现的取舍、贯穿全书的判断倾向 |
| **论文 / 报告** | 论证链 + 可复用方法 | 复用其方法与证据标准 | 有主张-证据-反驳结构、有方法章节 |
| **会议纪要 / 访谈** | 决策逻辑 | 复用其决策判据 | 有决策点、备选方案、否决理由 |
| **自己的工作流** | 环节 + 判据 + 坑 | 下次同类活直接跑 | 你刚和 AI 一起完成过一遍 |

抽取格式细则见 `references/`，按类型读对应的那一份，不要一次全读。

## 七步管线

```
1 Ingest   摄取   原材料 → 规范化 markdown     → references/ingest-formats.md
2 Probe    判定   类型判定 + 可蒸性评估         → scripts/probe.py
3 Extract  抽取   按类抽取，每条必须带出处      → references/<类型>.md
4 Compress 压缩   砍到一张 A4 装得下
5 Forge    锻造   产出 SKILL.md + references/   → references/skill-format.md
6 Install  安装   落 skills-repo，同步 Codex    → ⚠️ 需用户确认
7 Growth   成长   注入成长日志节                → assets/growth-section.md
```

## 硬约束（违反了产物就是废的）

1. **每条抽取必须带出处**（章节 / 页码 / 时间戳）。无出处的不进产物。
   蒸馏最典型的翻车方式是编造「作者说过」。这条是唯一有效的防幻觉闸门。

2. **Compress 后仍装不下一张 A4** → 回去重做 Extract，不要靠删内容凑。

3. **Install 是审批闸门。** skill 生成后停住等用户确认，不自动装进 skills-repo，不自动 commit。

4. **不搬原文。** 产物是判据与协议，不是摘抄。单条引用保持短。

5. **Probe 判为不可蒸** → 直接早退并说明理由，不要硬产一堆正确的废话。

## 快速开始

```bash
# 1. 摄取
python scripts/ingest.py --input "<书/论文路径>" --work "<工作目录>"

# 2. 判定类型 + 可蒸性
python scripts/probe.py --work "<工作目录>"

# 3. 按 probe 输出的类型，读对应 references/<类型>.md，做抽取与压缩
#    （Extract / Compress 是判断密集型环节，由你读文本后产出，不用脚本代劳）

# 4. 锻造 skill 骨架
python scripts/scaffold.py --work "<工作目录>" --name "<skill名>" \
    --category knowledge-management --install-to "<skills-repo>/skills"

# 5. 用一次之后追加成长日志
python scripts/growth_append.py --skill "<skill目录>"
```

## 双产物

除 skill 外，同时落 LLM-Wiki：

- **来源笔记** `sources/` —— 原材料本身作为一条来源
- **主题合集** `collections/` —— 按主题聚合
- **概念笔记** `concepts/` —— ⚠️ **仅当同一概念被 2 个以上独立来源提及时才创建**

第三条是 vault 自己的规则（见 `AGENTS.md`）。单本书蒸出的概念**不满足门槛**，
放在来源笔记与合集里，不要去 `concepts/` 建孤证笔记。

细则见 `references/wiki-schema.md`。

## 第二类蒸馏：把你自己干过的活蒸成 skill

这是最值钱的一条，也是最容易做假的。流程：

1. 和 AI 一起完成一件你以后会重复干的事
2. 让 AI 复盘：这次经历了哪些工作环节
3. 挑出**最有价值的那部分**环节，提炼成 skill（按 `references/workflow.md`）
4. 加成长功能 —— 让它用一次长一次

**成长功能要加确认闸门。** 自动追加而不审核，用几次就会自我污染成互相矛盾的补丁堆。
每次追加必须经用户确认后再写入。
