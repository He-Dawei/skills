# 自己的工作流 → 蒸成 skill

这是第二类蒸馏，也是最值钱的一条。

**触发时机**：你刚和 AI 一起完成了一件以后会重复干的事。

## 四步

```
1. 复盘    这次一共经历了哪些工作环节
2. 筛选    挑出最有价值的那部分
3. 提炼    写成 skill
4. 成长    加自我修正机制
```

## 第 1 步：复盘环节

让 AI 列出这次从头到尾做的事。**要列全，包括失败的尝试。**

分三类：
- **有效环节** —— 推进了任务的
- **试错环节** —— 走了弯路然后回头的
- **不可省略的检查** —— 省了就会出事的

第三类最容易被漏，也最值钱。

## 第 2 步：筛选

**不是所有环节都值得进 skill。** 判据：

| 保留 | 剔除 |
|---|---|
| 以后每次都要做的 | 一次性的环境搭建 |
| 判断密集的（需要经验） | 机械操作（一条命令的事） |
| 踩过坑的 | 顺理成章的 |
| 有明确判据的 | 靠感觉的 |

一个 skill 装 3–7 个环节最合适。超过 10 个说明粒度太细，合并。

## 第 3 步：提炼格式

```
环节：<这件事分几步做>
每步判据：<怎么算这步做完了>
踩过的坑：<这次在哪翻车、怎么爬出来的>
不可省略的检查：<省了就会出事的动作>
```

**「每步判据」必须可验证。** 「检查一下是否合理」不是判据，「输出行数 ≥ 输入去重后行数」是判据。

## 第 4 步：成长功能

在生成的 SKILL.md 末尾加成长日志节（模板见 `assets/growth-section.md`）。

配套 `scripts/growth_append.py` 做半自动追加。

**必须有确认闸门。** 自动追加而不审核，用几次就会自我污染成互相矛盾的补丁堆。
每次追加经用户确认后再写入，写入前 grep 是否与已有条目冲突。

## 反模式

- ❌ 把这次任务的**内容**写成 skill（应该写**方法**）
- ❌ 环节过多过细（「打开文件」「保存文件」不该是环节）
- ❌ 判据写成感觉描述
- ❌ 加成长功能但不加确认闸门
