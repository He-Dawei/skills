# 工具书 → 蒸方法论

工具书 = 教你怎么做一件事的书（操作手册、方法指南、实战教程）。

**蒸它的方法论。** 目的：以后遇到同类问题，直接套它的步骤，不用重新想。

## 判定特征

- 通篇是「第一步…第二步…」
- 有清单、有模板、有检查表
- 章节标题是动作（「如何搭建 X」「怎么避免 Y」）
- 读完你手上多了一套流程

## 抽取单元：四元组

每条方法论抽成：

```
问题：<什么场景下用得上>
步骤：<1..n，具体到能做>
判据：<做到什么程度算对 / 怎么知道该停了>
例外：<什么情况下这套不适用>
出处：<章节 / 页码>
```

**判据这一栏最容易漏，也最值钱。** 大多数工具书只写「怎么做」，不写「做到什么程度算好」。
如果原书确实没写判据，标注 `判据：原书未给出`，不要自己编一个。

**例外这一栏同理。** 作者若没说不适用场景，不要替他补。空着就空着。

## 抽取顺序

1. 先扫目录，把书切成方法论单元（一个单元 = 一个可独立使用的做法）
2. 逐个单元抽四元组
3. 合并重复单元（同一做法在不同章节反复出现时）
4. 剔除明显是凑字数的章节（「写在最后」「致谢」这类）

## 压缩原则

- 一本书通常能压到 5–15 个方法论单元
- 超过 20 个，说明切得太碎，合并相邻单元
- 少于 3 个，说明这不是工具书，回去重新 Probe

## 反模式

- ❌ 把书的章节结构照搬成产物结构（那是目录，不是方法论）
- ❌ 只抽「是什么」不抽「怎么做」（那是概念书，走 idea-book.md）
- ❌ 抽出来的步骤里出现「根据实际情况判断」这种没法执行的表述 —— 要么补具体判据，要么标为未给出
