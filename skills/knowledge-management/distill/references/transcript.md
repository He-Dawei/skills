# 会议纪要 / 访谈 → 蒸决策逻辑

**蒸决策逻辑。** 目的：复用对方在类似局面下的判断依据，而不是复用他这一次的结论。

## 判定特征

- 有多方发言，有来回
- 出现「那我们就这样定」「先不做 X」这类收口语句
- 有被否决的方案
- 有时间戳或发言人标记

## 抽取单元

```
决策：<定了什么>
备选：<当时还考虑了什么>
否决理由：<为什么没选那些 —— 这条最值钱>
未决项：<悬而未决的，以及卡在哪>
出处：<时间戳 / 发言人>
```

## 为什么「否决理由」最值钱

决策本身高度依赖当时的情境，换个时间地点就不适用。
但**否决理由**揭示的是判断标准 —— 什么条件下一个方案会被枪毙。
标准比结论稳定得多，也更容易迁移到新场景。

同理，「未决项」告诉你决策的边界在哪：什么事情当时想不清楚。

## 从多人发言里提决策逻辑

1. 先切出「决策点」—— 一次讨论中真正收口的地方通常没几处
2. 每个决策点往前找备选方案
3. 找否决理由：通常在收口之前的几轮来回里
4. 区分**决策者**与**建议者**：谁拍板，谁只是提建议。别把建议当成决策

## 说话人可信度

如果同一场对话里有立场冲突的发言，标注发言人身份与立场，
不要把某一方的说法当成客观事实。

若发言人身份不明（转写稿常见），标 `发言人未识别`，不要猜。

## 转写稿的特殊问题

- 语音转写会有错别字和同音词错误，影响判断的段落要标注「转写可能有误」
- 口语里的「这个那个」等填充词应当在抽取时剔除，但不要改动词意
- 无时间戳的稿子，用发言顺序代替出处

## 反模式

- ❌ 写成会议纪要式的「讨论了 A，讨论了 B」（那是流水账，不是决策逻辑）
- ❌ 只记结论不记否决理由
- ❌ 把某一方的立场包装成客观结论
